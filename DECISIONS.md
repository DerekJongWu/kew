# Decisions

Newest first. One entry per decision: what was decided, why, and what it rules out.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-25 | One-click actions (Log send, Move to, We met, status changes) show a toast whose Undo reverts only that action, and refuses with a reason if anything changed since. ⌘Z still undoes the newest action | Users need a visible confirmation, and an Undo button must never revert something other than what it names |
| 2026-11-25 | ⌘K ranks exact name, then name prefix, then word prefix, records before note text. "Search notes for …" is pinned first but Return opens the top record unless the user arrows to it | Typing a company's first letters should open that company. Full-text search stays one keystroke away |
| 2026-11-25 | Empty properties collapse behind "Show N empty fields"; empty values read "Empty"; dates read "24 Nov" (year added when not this year). Display only: files keep YYYY-MM-DD | Company pages had a 16-row block pushing notes below the fold, and five placeholder styles and two date formats looked unfinished |
| 2026-11-25 | Pipeline filters fold into one "Filter · N" button; the board fades its edge when columns overflow; "Move to…" lists every stage from the schema | Three rows of controls sat above the first card, and cards could not be passed or made Active from the menu |
| 2026-11-25 | `[[links]]` to records that don't exist show dashed and offer "Create <name>"; `[[Name#Heading]]` resolves to Name | Broken links looked identical to working ones |
| 2026-11-25 | On narrow windows a record's properties stack above its notes, not below | Below about 1080 px the properties used to drop under a long note and became unreachable |
| 2026-11-24 | The v1 app is Electron + TypeScript + React, with the built-in `node:sqlite` (FTS5) index and an isomorphic-git history stored in the app's support folder | One codebase that runs on any Mac with no native modules to compile. The index can always be rebuilt from the files, so it is never the source of truth. |
| 2026-11-24 | Every change to the vault goes through one write path: write atomically, record hand edits to history first, roll back on failure. Only first-time setup creates files outside it, and never overwrites | A user's notes must never be lost or half-written. Undo can always replay one action. |
| 2026-11-24 | Case-only renames ("acme" → "Acme") and names starting with a dot are refused | macOS treats the two names as the same file, so undo could delete the note. Dot files are hidden by Obsidian and skipped by the index. |
| 2026-11-24 | Schema changes are refused while `.kew/schema.yaml` has an error; Kew shows the last valid version and asks the user to fix or undo | Kew must never overwrite a file the user is hand-editing. |
| 2026-11-24 | History snapshots only notes and `.kew` settings when a vault is first opened; other files are recorded when first touched | Copying a data room's PDFs and videos into history made first open slow and doubled disk use. |
| 2026-11-24 | Ship as ad-hoc signed DMGs for Apple Silicon and Intel (macOS 13+), installed with "Open Anyway"; no auto-update | Beta testers accept the one-time Gatekeeper step, and it avoids the Apple developer account until wider release. Developer ID signing and notarization are a config switch away. |
| 2026-11-24 | The window cannot navigate or accept dropped files, and opens only https links in the browser | The window holds full write access to the vault, so no other page may ever load into it. |
| 2026-11-24 | `KEW_HOME` overrides the home folder Kew uses for default vault locations. Only the test scripts set it | Lets the end-to-end test run the packaged app without touching the real Documents folder. |
| 2026-11-24 | No git remote or cloud backup in v1. Undo and history come from a local git repository stored outside the vault, with no remote | Keeps Kew a purely local app with nothing to set up. Users back up with their own tools (Time Machine, iCloud). A `.git` folder inside a synced vault gets corrupted, so the history lives in the app's support folder. Rules out the prototype's push-to-GitHub. |
| 2026-11-24 | Diligence is a tabbed workspace per company. Tabs show what's already collected (with sources, conflicts and gaps) before any chat; a files tab covers the data room | The investor should see what's known before asking for more homework. Tabs are built from research notes tagged by `topic` and facts read from attachments, so they stay plain files and users can add their own tabs. |
| 2026-11-24 | Connectors are out of v1. Future roadmap: connectors, then user routines (skill + trigger), then community (sharing theme research and deals between users) | Keeps v1 focused on the core loop. Meetings come in by dropping a transcript until connectors land. Each stage builds on the one before. |
| 2026-11-24 | The copilot's output is notes. It has a side panel and a full-screen diligence workspace; new notes apply right away with undo, edits to existing notes need approval | Diligence is only worth something once it's in the vault and linked to companies and themes. Approving every new paragraph would be friction with no safety gain. |
| 2026-11-24 | Users can edit fields, options and templates; the schema lives in the vault. Only system fields (id, type, name, pipeline status, outreach dates) are fixed | Investors work differently and want to shape their own system. Ship starter templates, but don't lock them. Rules out a schema hard-coded in the app. |
| 2026-11-24 | Four primitives (company, person, meeting, theme), plus research notes and attachments. Inbound merges into Company; every contact gets a Person note with a `met` flag | The prototype vault's Inbound/Company split and the met-only People rule caused file moves, cross-folder dedupe and copied outreach history. In an app these become views. Rules out folders as status. |
| 2026-11-24 | V1 is desktop only: one investor on one machine, no mobile or multi-device sync | Keeps the MVP local with no backend to run. Git stays a backup. The sync design (git vs. file sync vs. a hosted service) is deferred and should be shared with team mode when it comes. |
| 2026-11-23 | Name the product **Kew** | A nod to Q from James Bond: the quartermaster who equips the agent. Short and ownable in the VC-tools space (trademark check still open). |
| 2026-11-23 | Build a product for associates and partners at any firm, not a Canaan-internal tool | The workflow is general; the prototype proved it on one real vault. |
| 2026-11-23 | Local-first markdown vault as the system of record; Obsidian optional | Users own their data, Claude can read it directly, and there's no lock-in. |
| 2026-11-23 | Claude access via the Agent SDK with bring-your-own API key for the beta | Anthropic doesn't allow third-party products to use claude.ai login without approval. |
